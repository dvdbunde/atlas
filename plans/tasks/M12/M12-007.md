# M12-007 --- Cross-application consistency, responsive, and accessibility pass

## Objective

Perform the final M12 validation and correction pass across the existing
ATLAS Blazor UI to ensure the approved visual language is consistently
applied and does not introduce responsive or accessibility regressions.

## Context

After the global, shell, shared-component, Citizen, Officer, and Admin
work, the application needs a cross-cutting review rather than another
redesign pass.

## Requirements

- Review all in-scope Blazor pages for inconsistent colours,
    typography, spacing, borders, controls, cards, tables, badges, and
    page headers.
- Remove accidental page-specific styling that conflicts with the
    shared M12 language.
- Validate the six representative screens: Citizen Dashboard, Citizen
    Permit Creation, Officer Dashboard, Officer Review, Admin Dashboard,
    Admin Operations.
- Validate desktop, tablet, and narrow/mobile presentation.
- Validate keyboard focus and navigation.
- Validate colour contrast and semantic status presentation.
- Fix only issues required to satisfy the M12 specification; do not
    expand scope into redesign.

## Relevant files / areas

- `src/ATLAS.Blazor/`
- `src/ATLAS.Blazor/wwwroot/app.css`
- `src/ATLAS.Blazor/Components/Layout/`
- `src/ATLAS.Blazor/Components/Pages/`
- `src/ATLAS.Blazor/Components/Shared/`

## Acceptance criteria

- [ ] All in-scope pages visibly belong to one ATLAS visual system.
- [ ] No known page retains the old blue/purple gradient shell
    styling.
- [ ] Shared controls and status treatments are consistent across
    roles.
- [ ] No new unintended horizontal overflow is introduced at supported
    widths.
- [ ] Keyboard focus is visible on reviewed interactive controls.
- [ ] Reviewed text/control combinations meet the project's
    accessibility expectations for contrast.
- [ ] Existing functional workflows remain intact.
- [ ] No invented functionality has been introduced during M12.
- [ ] Existing automated tests and CI checks pass.

## Testing

- [ ] Run the complete relevant automated test suite.
- [ ] Perform the six-screen visual review.
- [ ] Perform desktop/tablet/narrow responsive checks.
- [ ] Perform keyboard accessibility review.
- [ ] Perform contrast/accessibility checks available in the project.
- [ ] Record any intentional deviations from the M12 specification.

## Documentation

- [ ] Update the M12 implementation report with validation results and
    any deviations.
- [ ] Update the milestone plan if acceptance criteria or scope
    changed during implementation.

## Constraints

- This is a correction and validation pass, not a new redesign phase.
- Preserve existing pages, components, workflows, and information
    architecture.
- Do not add functionality to resolve visual issues.
- Keep changes minimal and directly tied to M12 acceptance criteria.

closure.
