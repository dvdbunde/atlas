# M12-001 --- Global visual foundation

## Objective

Establish the global ATLAS visual styling foundation used by the
existing Blazor application, including colour tokens, typography,
spacing, surfaces, controls, borders, focus states, and semantic states.

## Context

The current application uses largely default Blazor/Bootstrap styling.
M12 requires a restrained ATLAS visual language while preserving the
existing page and component architecture.

## Requirements

- Define ATLAS CSS custom properties for the approved primary, shell,
    neutral, and semantic colours.
- Define the approved typography stack and hierarchy.
- Define the shared spacing scale.
- Define global page, surface, border, control, focus, and validation
    styling.
- Restyle standard Bootstrap-derived links, buttons, form controls,
    and common elements where appropriate.
- Remove the current default-Blazor visual treatment without replacing
    Bootstrap.
- Keep styling reusable and avoid page-specific one-off rules unless
    required.

## Relevant files / areas

- `src/ATLAS.Blazor/wwwroot/app.css`
- `src/ATLAS.Blazor/Components/App.razor`
- Existing Bootstrap CSS under
    `src/ATLAS.Blazor/wwwroot/lib/bootstrap/dist/`

## Acceptance criteria

- [ ] Global ATLAS colour tokens are defined and used for shared
    styling.
- [ ] The approved navy/blue/neutral/semantic colour strategy is
    implemented.
- [ ] Typography and spacing have a consistent global baseline.
- [ ] Default Bootstrap/Blazor links, buttons, inputs, focus states,
    and validation presentation are visually aligned with M12.
- [ ] No new UI framework or component library is introduced.
- [ ] Existing application functionality is unchanged.

## Testing

- [ ] Run the existing test suite relevant to the Blazor application.
- [ ] Render representative existing pages and verify the global
    styles apply consistently.
- [ ] Keyboard-check representative links, buttons, and form controls
    for visible focus.

## Documentation

- [ ] Update M12 planning documentation only if the implemented token
    values materially differ from the approved specification.

## Constraints

- CSS-first implementation.
- Do not rebuild components.
- Do not change application behaviour.
- Keep Bootstrap as the underlying framework.
- Do not add invented UI.

## Notes

This is the foundation for M12-002 through M12-006. Exact colour values
may be tuned during implementation while preserving the approved visual
direction.
