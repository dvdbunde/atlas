# M12-006 --- Admin pages restyling

## Objective

Apply the M12 visual language across the existing Admin pages,
prioritising operational clarity and information density while
preserving current functionality.

## Context

Admin contains the largest collection of pages and tables. The goal is
consistent styling, not a new administration information architecture.

## Requirements

- Restyle the existing Admin Dashboard.
- Restyle the existing Operations page.
- Restyle existing Admin list, detail, designer, audit, application,
    email-template, user, reference-data, and settings pages.
- Preserve existing tables, filters, forms, actions, statuses, and
    navigation.
- Use existing shared components after M12-003.
- Improve page density and hierarchy through styling and small layout
    adjustments only.
- Validate the Admin Dashboard and Operations screens against the
    approved visual direction.

## Relevant files / areas

- `src/ATLAS.Blazor/Components/Pages/Admin/`
- `src/ATLAS.Blazor/Components/Shared/Admin/`
- `src/ATLAS.Blazor/Components/Shared/`

## Acceptance criteria

- [ ] Existing Admin pages use the common M12 visual language.
- [ ] Admin Dashboard retains its existing information and
    functionality.
- [ ] Operations page retains its existing operational information and
    controls.
- [ ] Existing tables, filters, forms, badges, and actions remain
    functional and visually consistent.
- [ ] Admin pages have appropriate information density without
    becoming visually cluttered.
- [ ] No new Admin functionality is introduced.
- [ ] Representative desktop and narrow layouts remain usable.

## Testing

- [ ] Run relevant Admin tests.
- [ ] Verify representative list/detail/configuration workflows.
- [ ] Verify Operations page behaviour and existing status
    information.
- [ ] Perform keyboard and responsive checks.

## Documentation

- [ ] None required.

## Constraints

- Preserve the existing Admin information architecture.
- Do not add new reports, widgets, monitoring features, or navigation
    items.
- Do not rebuild existing Admin components/pages.
- Prefer CSS-first changes.

## Notes

Primary visual references: supplied Admin Dashboard and Admin Operations
screenshots/mockups.
