# M12-003 --- Existing shared component restyling

## Objective

Restyle the existing shared Blazor components so common UI patterns
consistently use the M12 visual language.

## Context

ATLAS already has shared components for status, application summaries,
timelines, activity, document requirements, page headers, empty states,
application details, and dynamic forms. These components should be
preserved and visually upgraded rather than replaced.

## Requirements

- Restyle `StatusBadge`.
- Restyle `ApplicationSummaryCard`.
- Restyle `ApplicationTimeline`.
- Restyle `ApplicationActivityFeed`.
- Restyle `DocumentRequirementCard`.
- Restyle `Shared/Admin/PageHeader`.
- Restyle `Shared/Admin/EmptyState`.
- Restyle `ApplicationDetails/ApplicationDetailsLayout`.
- Restyle `DynamicFormGenerator`.
- Use the global M12 tokens and patterns instead of duplicating
    values.
- Make only small targeted markup changes where styling alone cannot
    achieve the required result.

## Relevant files / areas

- `src/ATLAS.Blazor/Components/Shared/StatusBadge.razor`
- `src/ATLAS.Blazor/Components/Shared/ApplicationSummaryCard.razor`
- `src/ATLAS.Blazor/Components/Shared/ApplicationTimeline.razor`
- `src/ATLAS.Blazor/Components/Shared/ApplicationActivityFeed.razor`
- `src/ATLAS.Blazor/Components/Shared/DocumentRequirementCard.razor`
- `src/ATLAS.Blazor/Components/Shared/Admin/PageHeader.razor`
- `src/ATLAS.Blazor/Components/Shared/Admin/EmptyState.razor`
- `src/ATLAS.Blazor/Components/Shared/ApplicationDetail/ApplicationDetailsLayout.razor`
- `src/ATLAS.Blazor/Components/Shared/DynamicFormGenerator.razor`

## Acceptance criteria

- [ ] Existing shared components retain their existing
    responsibilities and parameters.
- [ ] Shared components use consistent M12 surfaces, borders, spacing,
    typography, and semantic states.
- [ ] Status badges use the approved semantic colour strategy.
- [ ] Page headers and empty states have consistent hierarchy and
    spacing.
- [ ] Application detail/timeline/activity/document patterns look
    coherent.
- [ ] Dynamic forms visually align with the global form treatment.
- [ ] No new shared component architecture is introduced.
- [ ] Existing component behaviour remains unchanged.

## Testing

- [ ] Run tests covering changed shared components.
- [ ] Verify representative usages in Citizen, Officer, and Admin
    pages.
- [ ] Check keyboard focus and form validation presentation where
    applicable.

## Documentation

- [ ] None required unless shared styling conventions change from the
    approved specification.

## Constraints

- Existing components are the source of truth.
- Prefer CSS changes over Razor restructuring.
- Do not invent new component functionality.
- Do not introduce another UI framework.

## Notes

This task should establish consistency for the page-specific work that
follows.
