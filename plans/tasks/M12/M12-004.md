# M12-004 --- Citizen pages restyling

## Objective

Apply the M12 visual language to the existing Citizen-facing pages while
preserving their current information, workflows, and components.

## Context

Citizen pages should feel calm, clear, and reassuring. The work is a
visual restyling effort, not a redesign of the citizen workflow.

## Requirements

- Restyle the existing Citizen Dashboard.
- Restyle the existing permit selection and permit/application
    creation flow.
- Restyle existing application edit/detail/confirmation pages where
    applicable.
- Preserve existing content, actions, validation, and navigation.
- Use the existing shared components after M12-003.
- Improve page spacing, hierarchy, and form grouping only where it
    supports the visual treatment.
- Validate the Citizen Dashboard and Permit Creation screens against
    the approved visual direction.

## Relevant files / areas

- `src/ATLAS.Blazor/Components/Pages/CitizenDashboard.razor`
- `src/ATLAS.Blazor/Components/Pages/PermitSelection.razor`
- `src/ATLAS.Blazor/Components/Pages/ApplicationCreate.razor`
- `src/ATLAS.Blazor/Components/Pages/ApplicationEdit.razor`
- `src/ATLAS.Blazor/Components/Pages/ApplicationDetail.razor`
- `src/ATLAS.Blazor/Components/Pages/ConfirmationPage.razor`
- `src/ATLAS.Blazor/Components/Shared/`

## Acceptance criteria

- [ ] Citizen Dashboard retains its existing information and actions
    while receiving the M12 styling.
- [ ] Permit creation retains its existing fields, validation, and
    workflow while receiving the M12 styling.
- [ ] Existing application detail/edit/confirmation presentation is
    visually consistent with the Citizen Dashboard.
- [ ] Existing shared components are used unchanged functionally.
- [ ] No new Citizen functionality is introduced.
- [ ] The Citizen experience is visually calmer and clearer than the
    current Bootstrap/default-Blazor appearance.
- [ ] Representative desktop and narrow/mobile layouts remain usable.

## Testing

- [ ] Run relevant Citizen/application tests.
- [ ] Exercise permit creation through the existing workflow.
- [ ] Verify validation and existing actions.
- [ ] Perform keyboard and responsive checks.

## Documentation

- [ ] None required.

## Constraints

- Preserve Citizen workflows and information architecture.
- Do not rebuild the pages.
- Do not add new dashboard features.
- Prefer CSS-first changes.

## Notes

Primary visual references: supplied Citizen Dashboard and Citizen Permit
Creation screenshots/mockups.
